# Шпаргалка для демонстрации

## Порядок показа

1. Объяснить, что в работе три задания, а восемь — это примеры внутри задания 1.
2. Запустить `./run-task1.sh` и открыть `reports/task1-examples.html`.
3. Запустить `./run-task2.sh` и открыть `reports/task2-library.html`.
4. Запустить `./run-task3.sh` и открыть `reports/colt-spotbugs.html`.

Если нужно подробно показать первый раздел, каждый пример запускается отдельно:

```bash
./run-example.sh 1
./run-example.sh 3
./run-example.sh 6
./run-example.sh 7
```

## Что сказать

Компилятор проверяет допустимость программы по правилам Java. SpotBugs работает
после компиляции: исследует байткод и поток значений без запуска программы и
ищет известные опасные шаблоны. Поэтому код может успешно скомпилироваться, но
получить предупреждения о распаковке `null`, непотокобезопасном объекте,
погрешности `BigDecimal` или нарушении контракта `@Nonnull`.

Задание 3 показывает, что SpotBugs умеет анализировать уже собранный JAR. Для
удобства основной HTML ограничен десятью типами проблем из отчёта, а полный
результат сохраняется в `reports/colt-all-warnings.xml`.

Число предупреждений Colt отличается от 385 в документе, поскольку там не
зафиксированы версия и настройки анализатора. В репозитории используется
SpotBugs 4.10.4 с `effort=max` и порогом `low`.
